# 常见问答

## 使用前

**Q：这事儿会被发现吗？**

平台侧能观察到的是：这条视频的播放时长曲线、上报间隔、倍速。工具默认 1.25x、真实播放、真心跳，协议层面和真人观看只有倍率差异。倍速越高、上报越密，越不像真人。想最稳就用 `--rate 1.0`。

**Q：会不会导致账号被处罚？**
技术上的风险点集中在「上报异常」：短时间连续进度跳跃、多端并发登录、多个 IP 同时操作。这三点本文档都给了规避方式（低倍速、单账号串行、固定机器）。剩下的取决于平台规则本身，你自己权衡。

**Q：能代替我做章节测验吗？**
不能。工具只处理视频任务点。测验是另一套接口，需要单独做。

**Q：为什么不用直接伪造请求？那样不是更快？**

因为 `enc` 由前端算，而且服务端会比对「进度增量 / 真实时间间隔」。伪造要么拼 `enc`（改版即失效），要么被判定异常丢弃。驱动真播放器反而最省心。

**Q：脚本会不会上传我的数据？**
不会。所有代码都在本地，没有任何上报埋点。你可以自己 `grep` 验证：

```bash
grep -rniE 'fetch\(|XMLHttpRequest|sendBeacon' cx.user.js
```

命中的只有「识别页面自己的上报」那几处，没有向外发请求的代码。

## 安装 / 环境

**Q：必须装 Python 吗？**
不必。路线一用 Tampermonkey，零环境。想要「自动切下一节、整门课跑完」，才需要路线二的 Python。

**Q：能不能不装 git？**
可以。仓库页 **Code → Download ZIP**，解压后从 `cd` 开始。

**Q：公司电脑 / 校园网有限制怎么办？**
Playwright 需要下载约 90MB 的 Chromium，网络受限时改用路线一（纯浏览器，无额外下载）。

**Q：`.venv` 占了 145MB，正常吗？**
正常，里面是 Playwright 和它的依赖。`.gitignore` 已排除，不会进仓库。

## 运行中

**Q：能不能一边跑一边用电脑？**
可以。视频是静音的，CPU 占用很低。但别关窗口——Chromium 被关掉任务就断了。

**Q：能不能最小化窗口 / 切到别的应用？**
可以，脚本伪造了 `visibilityState`，切后台不会暂停。

**Q：一个课程跑完，怎么知道跑干净了？**
看课程页章节列表的任务点颜色：全绿就是完成。日志里最后一条应该是「没有找到下一节，可能已到本章末尾」。

**Q：中途停了，重跑会从头开始吗？**
不会。`progress.json` 记录课程级状态；同一门课重跑会重新扫章节，但已完成的任务点不会重复消耗时间（播放器直接跳过或本就不播）。

**Q：能不能指定只跑第 3 章？**
命令行没做章节选择。做法：手动点进第 3 章的第一节，然后用路线一（浏览器脚本接管），或用路线三按 `jobid` 精确补。

**Q：`rate` 设 1.25 会不会有的课不算？**
个别课程对倍率敏感。如果发现某门课进度不涨，单独用 `--rate 1.0` 跑一遍。

## 弹题

**Q：弹题答错会怎样？**
通常只影响那一道题的得分（有的课计入平时分），不影响视频进度。在意就把 `quizMode` 改成 `'pause'`。

**Q：能不能自动答对？**
可以自己维护题库：`cx.user.js` 的 `handleQuiz` 里，按题目文本匹配后点对应选项。没有内置题库——题是各校老师自己出的，公共题库命中率很低。

**Q：弹题出现时视频会暂停，脚本会自动恢复吗？**
会。`auto` 模式提交后自动继续；`pause` 模式等你答完点继续。

## 排查

**Q：日志里 `keepalive` 一直在打印，但进度不动？**
说明视频 `paused` 了但脚本以为在播。看 `__CX_STATUS__.paused`，若为 `true` 说明自动播放被拦（浏览器策略），见 [troubleshooting.md](troubleshooting.md) A2。

**Q：`Repository not found` / 推送失败？**
那是 git 的事，跟刷课无关。看 [SECURITY.md](../SECURITY.md) 和仓库根目录的推送说明。

**Q：更新脚本后旧登录态还能用吗？**
能。登录态在 `cx_profile/`，和代码版本无关。

## 其它

**Q：能跑在树莓派 / NAS 上吗？**
理论上可以（Playwright 支持 ARM64 Linux），但要装无头依赖，教程没覆盖。日常用电脑就行。

**Q：会持续维护吗？**
播放器前端一改版，选择器和 `enc` 顺序都可能变。提 issue 时带上脱敏后的 `__CX_STATUS__` 和日志片段，定位会快很多。

**Q：为什么仓库里没有截图？**
界面会变，截图很快过期。README 里给的是**可复制的预期输出文本**，比截图更耐用。
